# MovieLens Metrics Tree: Data Pipeline & Analytics

## О проекте

**MovieLens Metrics Tree** — это аналитическая система для обработки и исследования датасета MovieLens 25M. Проект демонстрирует подход к созданию надежных данных (Data Quality), построению автоматизированных ETL-пайплайнов и подготовке инфраструктуры для A/B тестирования.

**Ключевая цель:** Превратить сырые данные в надежный источник аналитики и подготовить рекомендации по улучшению продукта на основе метрик удержания.

---

## Основные возможности

 **Data Quality & Validation:** Автоматические тесты на целостность данных (дубликаты, NULL-значения, диапазоны оценок).  
 **ETL Pipeline:** Оптимизированная обработка данных с использованием **DuckDB**.  
 **Оркестрация:** Полностью контейнеризованный **Apache Airflow** для планирования и мониторинга задач.  
 **Аналитика:** Расчет ключевых метрик (Retention, Churn, Cohort Analysis).  
 **A/B Test Design:** Профессионально задокументированный дизайн эксперимента для улучшения Day-1 Retention.  
 **Визуализация:** Интерактивные графики Plotly для презентации результатов.

## Инструкция по запуску проекта

Требуется установленный Docker Desktop.

1.  Перейдите в папку `docker`:
    ```powershell
    cd docker
    ```
2.  Запустите контейнеры:
    ```powershell
    docker compose up -d
    ```
3.  Инициализации БД.
4.  Откройте **Airflow UI**: [http://localhost:8080](http://localhost:8080)
    *   **Login:** `admin`
    *   **Password:** `admin`
5.  Включите DAG `movielens_pipeline` и нажмите **Trigger**.

## Ключевые инсайты и результаты

В ходе анализа датасета MovieLens 25M были получены следующие выводы:

1.  **Качество данных:** Датасет чистый. Дубликаты отсутствуют, диапазоны оценок валидны (0.5 - 5.0).
2.  **Поведение пользователей:**
    *   **Day-1 Retention:** Низкий (~19%). Большинство пользователей пробуют платформу один раз и уходят.
    *   **Day-7 Retention:** Высокий (~100% для оставшихся). Те, кто вернулся на второй день, становятся лояльными.
3.  **Проблема "Холодного старта" (Cold Start):** Отсутствует. В датасете преобладают активные пользователи с историей оценок.
4.  **Временные паттерны:** Пик активности приходится на 00:00 UTC (полночь), что требует учета часовых поясов при анализе.

## Проектирование A/B теста

Для решения проблемы низкого удержания (Day-1 Retention) был разработан дизайн эксперимента:

**Файл:** [experiment_design.md](experiment_design.md)

*   **Гипотеза:** Скидка 20% на подписку при активации в понедельник повысит Day-1 Retention с 18% до 30%.
*   **Метрики:**
    *   Primary: Day-1 Retention Rate.
    *   Secondary: Day-30 Churn Rate (чтобы не привлекать "туристов").
*   **Статистика:** z-test для пропорций, требуемый размер выборки ~1000 пользователей.
